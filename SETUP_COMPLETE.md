### 🔧 Команды для разработки

```bash
# Проверка кода (TypeScript + HTML)
bun run lint

# Автоисправление ошибок
bun run lint:fix

# Форматирование кода
bun run format

# Проверка форматирования без изменений
bun run format:check

# Проверка стилей (CSS/SCSS)
bun run stylelint

# Автоисправление стилей
bun run stylelint:fix
```

### 🎯 Angular ESLint Правила

#### Селекторы компонентов и директив
- Компоненты: **kebab-case** с префиксом `app-` (например: `app-my-component`)
- Директивы: **camelCase** с префиксом `app` (например: `appHighlight`)

#### Жизненные циклы компонентов
- Требуется реализация интерфейса `OnInit` если используется `ngOnInit()`
- Запрещены пустые методы жизненного цикла

#### TypeScript
- Запрещено использование `any` типа
- Требуется явное указание типов для параметров функций
- Запрещены неиспользуемые переменные

#### Шаблоны HTML
- Проверка правильности синтаксиса двустороннего связывания `[(ngModel)]`
- Запрещены вызовы функций в шаблонах (используйте trackBy вместо this.method())
- Ограничение сложности условий в шаблонах

### 🚀 Автоматическая проверка при коммите

При попытке сделать коммит автоматически:
1. **pre-commit hook** запустит lint-staged, который проверит и исправит измененные файлы
2. **commit-msg hook** проверит формат сообщения коммита в соответствии с Conventional Commits

Формат коммита:
```
<type>(<scope>): <description>

<body>

<footer>
```

**Типы коммитов:**
- `feat` - новая функциональность
- `fix` - исправление бага
- `docs` - документация
- `style` - форматирование кода
- `refactor` - рефакторинг
- `perf` - оптимизация производительности
- `test` - добавление/изменение тестов
- `chore` - обновление зависимостей, конфиг и т.д.
- `ci` - изменения CI/CD
- `build` - изменения сборки

**Примеры:**
```
feat(components): добавлен новый компонент User Card
fix(routing): исправлена навигация между страницами
docs: обновлена документация
style: отформатирован код в app.component.ts
```
